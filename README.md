# AlarmDevice · 微信小程序

面向报警设备负责人的微信小程序，提供设备绑定、报警查看与确认、处理历史查询，以及报警位置和录音查看。

本仓库是 **AlarmDevice 的小程序客户端**，不包含生产 Java 后端。完整系统介绍、管理网站、数据库迁移和生产部署说明见 [alarmdevice](https://github.com/zhan-3/alarmdevice)。

## 仓库组成

| 仓库 | 职责 |
| --- | --- |
| [alarmdevice](https://github.com/zhan-3/alarmdevice) | 系统主入口：后端、管理网站、数据库迁移与部署文档 |
| [alarmdevice-miniprogram](https://github.com/zhan-3/alarmdevice-miniprogram) | 微信小程序：设备管理、报警处理与用户侧历史查询 |

小程序和管理网站复用后端服务，但分别开发、构建和发布，不需要合并仓库。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 登录与手机号验证 | 微信登录、短信验证码验证、微信官方隐私授权与指引阅读入口 |
| 设备管理 | 扫码或输入 SN 绑定设备、切换设备、维护个人设备别名 |
| 设备信息 | 查看设备状态、维护共享安装位置、管理额外报警联系人 |
| 待处理报警 | 查看报警事件、打开报警位置、人工确认处理 |
| 微信报警通知 | 手动开启一次通知，下一次需要再次开启 |
| 处理历史 | 按处理日期、处理人和关键词查询，下拉刷新与触底游标分页 |
| 历史详情 | 查看报警及处理时间、处理人、位置和受保护录音 |
| 设备录音列表 | 播放、暂停、调整进度与倍速，本地收藏及从列表移除 |

### 业务边界

- **“已处理”仅表示人工确认，不代表设备恢复正常。**
- 安装位置属于设备共享信息；报警位置属于某一次报警事件，二者不同。
- 设备别名属于当前用户，同一台设备可有不同用户别名。
- 处理历史只展示当前登录用户**仍绑定设备的已处理报警**，不要求由本人处理。
- 解绑后重新请求历史列表、详情和录音，服务端会重新校验访问权限。
- 录音列表的“从列表移除”是本地隐藏，不等于删除服务端文件。

## 技术与结构

采用原生微信小程序（JavaScript、WXML、WXSS），使用 `wx.request`、本地存储、地图及 `InnerAudioContext` 等平台能力；测试使用 Node.js 内置测试运行器。

```text
.
├── app.js / app.json / app.wxss   # 应用入口、页面注册与共享样式
├── pages/
│   ├── alarms/                   # 待处理报警与一次通知授权
│   ├── alarm-history/            # 游标分页历史列表及筛选
│   ├── alarm-history-detail/     # 历史详情与受保护录音
│   ├── home/                     # 设备列表
│   ├── device-detail/            # 设备位置、别名及联系人
│   ├── devicebinding/            # 扫码/手动绑定
│   ├── audio/                    # 设备录音列表与播放器
│   ├── login/                    # 登录与手机号验证
│   └── setting/                  # 账号与设置
├── components/                   # 图标、面板和按钮等组件
├── utils/                        # 认证、HTTP、设备与报警数据逻辑
├── test/                         # Node 页面行为与业务逻辑测试
├── docs/                         # 项目及参考文档
├── images/                       # 图标与图片资源
└── server/                       # 本地 Mock 服务及服务说明静态页面
```

`server/` 不是生产后端，也不是管理网站；其中 Mock 接口可能滞后于真实后端，不应作为最新接口契约。

## 快速开始

### 1. 准备环境

- 安装微信开发者工具，使用有对应小程序权限的微信账号登录。
- 安装较新的 Node.js LTS，用于执行 `node --test`。
- 如需真实登录、短信验证和设备绑定，需要可用的后端、微信配置及测试设备。

### 2. 获取源码

```bash
git clone git@github.com:zhan-3/alarmdevice-miniprogram.git
cd alarmdevice-miniprogram
```

在微信开发者工具中导入仓库根目录，确认 `project.config.json` 的 AppID 与有权限的小程序一致。本仓库当前无 npm 运行时依赖，日常小程序编译不依赖构建 Mock 服务。

### 3. 配置接口地址

编辑 [`utils/env.js`](utils/env.js) 中的 `API_BASE_URLS`：

| 环境 | 当前默认地址 |
| --- | --- |
| develop | `https://bridgemonitor.xyz` |
| trial | `https://bridgemonitor.xyz` |
| release | `https://bridgemonitor.xyz` |

真实环境需在微信后台配置相应的 request、downloadFile 等合法域名。真机访问本地服务时不能使用电脑的 `127.0.0.1`；请按实际网络和微信限制配置可访问地址。

### 4. 编译与验证

在开发者工具中编译，完成微信登录、手机号验证，再绑定有权访问的测试设备。首次联调建议依次检查：

1. 登录与验证码流程。
2. 设备绑定、别名和安装位置。
3. 待处理报警确认与历史列表刷新。
4. 历史筛选、详情、录音下载与播放。
5. 解绑后的权限复验、网络失败重试及离开页面后的录音清理。

开发者工具验证不能代替真机验收，尤其是订阅通知、地图、隐私授权与音频播放。

## 微信后台配置

- **AppID 与服务端登录配置**：与实际小程序保持一致；AppSecret、JWT 密钥和数据库配置仅保留在服务端，不得写入本仓库。
- **合法域名**：配置实际使用的 API 请求与录音下载域名。
- **订阅消息模板**：[`app.js`](app.js) 的模板 ID 必须属于实际小程序，并与服务端消息发送逻辑一致。通知是单次授权，不是持续订阅。
- **用户隐私保护指引**：在微信后台按实际收集的信息和用途填写并完成平台审核。登录页通过 `wx.openPrivacyContract` 打开平台指引，不是自定义网页链接。
- **位置相关能力**：保持微信后台声明、`app.json` 权限用途与实际业务一致。

> 隐私授权：登录、发送验证码及验证手机号前调用 `wx.requirePrivacyAuthorize`，由微信官方弹窗完成用户同意状态同步；已同意的用户由微信直接返回成功。未完成授权不继续操作，页面不再使用自定义复选框。后台隐私指引已审核通过，官方弹窗与协议打开效果仍需在对应 AppID 的开发者工具及真机上验收。

## 认证与接口约定

- **登录凭证**用于用户级操作，如设备绑定、待处理报警及历史查询。
- 所有受保护请求复用同一个用户 JWT，不再存储或换发设备专用凭证。
- 当前选中设备只保存在客户端。设备接口显式传 `deviceId`，后端通过用户已验证手机号和设备绑定实时鉴权；本人绑定和额外通知联系人绑定暂视为等同。
- `401` 清除登录状态；设备范围请求的 `403` 只移除该设备的本地缓存，不清除登录凭证。
- 启动时保留旧设备名称和选中项，但清除旧设备凭证。接口变更需要前后端协调发布；详见[后端认证契约](https://github.com/zhan-3/alarmdevice/blob/main/docs/mini-program-authentication.md)。
- JSON 接口沿用 `Result`：成功 `code: 1`，数据位于 `data`；业务失败与 HTTP 失败由请求层统一处理。
- 历史接口中的 ID 按字符串处理；游标原样传回，不由客户端解析。
- 处理日期范围是北京时间，左闭右开；选择截至某天时，客户端传次日零点作为上界。
- 历史录音通过登录授权下载到临时文件后播放，不在 URL 中传 token，不根据 `fileId` 拼公共录音地址。

最新契约以[后端接口文档](https://github.com/zhan-3/alarmdevice/blob/main/docs/mini-program-handling-history.md)及后端实现为准，不在本 README 重复维护完整接口手册。

```bash
# 全部 Node 测试
npm test

# 只验证处理历史及其入口
node --test test/alarm-history-page.test.js test/alarm-history-detail.test.js test/alarm-page.test.js
```
